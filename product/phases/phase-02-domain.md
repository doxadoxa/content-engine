# Фаза 2 — Доменная модель и Brand Brief

**Покрывает:** Phase 0 спеки, §2 и §3.1.
**Зависит от:** фазы 1 (тенант, локали, панель).

## Цель

Положить в БД всю модель §2 так, чтобы дальнейшие фазы только добавляли
поведение, а не меняли схему. Заполнить Brief для первых двух проектов руками —
это одновременно и продуктовая задача, и набор эталонных примеров для
онбординг-агента фазы 9.

## Скоуп

### 2.1 Сущности

- **BrandBrief** — версионируемый. Каждое сохранение — новая версия; активная
  одна. Поля: позиционирование, ЦА, тон, запретные темы, визуальный язык,
  примеры «нравится / не нравится», конкуренты. Метод компиляции в промпт —
  заглушка с тестом на детерминированность (потребитель появится в фазе 3).
- **Channel** — цель публикации: `webhook | wordpress | linkedin | x | telegram
  | pull_api`. В этой фазе — только запись конфигурации и секрета; доставка в
  фазе 6. Секрет шифруется в БД.
- **ContentPlan** — месячный, `draft → approved`.
- **ContentItem** — контент-юнит:
  - `locale`, `locale_group_id` — локали как отдельные строки, связанные группой;
  - `parent_id` — производные (дети) от статьи-родителя;
  - state machine `idea → queued → generating → draft → approved → published →
    refreshing`, переходы только через явный метод, недопустимый переход —
    исключение;
  - тип (`how_to | explainer | product | comparison`), метрики темы
    (difficulty, volume), целевой запрос, сущности.
- **Asset** — изображения: роль (`hero | inline`), якорь размещения, размеры.
- **PipelineRun** — таблица создаётся здесь, наполняется в фазе 3.
- **WebhookDelivery** — таблица создаётся здесь, наполняется в фазе 6.

### 2.2 Правила, которые обязаны быть в БД, а не в коде

- уникальность `(locale_group_id, locale)` — одна локаль в группе одна;
- уникальность `(project_id, slug, locale)`;
- каскад/запрет удаления родителя с производными;
- `project_id` NOT NULL на всех тенантных таблицах, FK с `on delete cascade`.

### 2.3 Панель

Экраны Inertia в дэшборде оператора: BrandBrief (форма + история версий с
диффом), Channel (список, без мастера подключения — он в фазе 7), ContentItem
(read-only список). Project уже есть с фазы 1.

Изначально здесь были написаны Filament-ресурсы. Filament удалён в фазе 1 —
его единственный экран дублировал дэшборд, а держать его означало второй логин
на втором URL. Возвращать его ради трёх экранов, которые всё равно должны жить
рядом с переключателем проектов, значит вернуть ровно ту проблему.

## Вне скоупа

Генерация чего-либо, вызовы моделей, доставка, календарь, аппрувы.

## Критерий выхода

1. Brief для двух проектов заполнен, изменение тона даёт новую версию, старая
   доступна и помечена, какие публикации на ней сделаны.
2. Юнит проходит весь путь state machine программно; каждый недопустимый переход
   даёт исключение — по тесту на переход.
3. Юнит с двумя локалями и тремя производными строится и читается одним запросом
   без N+1 (тест считает запросы).
4. Фабрики есть у всех сущностей — дальше без них тесты не пишутся.
