# Фаза 6 — Webhook-адаптер и пакет `engine-receiver`

**Покрывает:** Phase 0 спеки, §5, §4 (пайплайн 5).
**Зависит от:** фазы 5.

> **Блокер:** §5 ссылается на `webhook-publish-adapter-spec.md`, которого в
> репозитории нет. Фаза начинается с написания этой спеки — контракт доставки
> нельзя «дореализовать потом», его видит внешняя сторона.

## Цель

Универсальная доставка контента наружу: полный контракт, а не «дёрнули URL».
Это второе место дифференциации от BLG (§1.3, §5): без `content.updated` не
работает refresh фазы 9, без `public_url` от приёмника не работает матчинг с GSC.

## Скоуп

### 6.1 Контракт

- События: `content.published`, `content.updated`, `content.deleted`, `ping`.
- Bearer + подпись HMAC-SHA256 + timestamp против replay-атак.
- Идемпотентность по `delivery_id`.
- Payload: одна локаль на доставку, `locale_group_id` для hreflang, markdown +
  html, массив изображений с якорями, `json_ld` + `faq_json_ld`, author (E-E-A-T),
  `internal_links`.
- Ответ приёмника содержит `public_url` → сохраняется в юнит.

### 6.2 Доставка

- Ретраи с backoff: 1м → 5м → 30м → 2ч → 12ч.
- Dead-letter после исчерпания попыток.
- Replay доставки (из кода здесь, из дэшборда — фаза 7).
- `WebhookDelivery`: `delivery_id`, статус, код ответа, латентность,
  `payload_snapshot`.

Снапшот payload обязателен: без него replay отправляет сегодняшнюю версию
контента под вчерашним `delivery_id`, и приёмник не может отличить повтор от
изменения.

### 6.3 Пакет `engine-receiver`

Composer-пакет для сайта-приёмника: endpoint + миграция + рендер. Цель из §5 —
подключение сайта за 10 минут. Проверка подписи и идемпотентность — на стороне
пакета, чтобы приёмник не мог их «забыть».

## Вне скоупа

Батч-доставка, mTLS, ротация секрета через UI (§10). WordPress и соцканалы —
фаза 8. Pull API — фаза 9.

## Критерий выхода

1. Приёмник на `engine-receiver` поднимается с нуля и принимает публикацию.
2. Повтор доставки с тем же `delivery_id` не создаёт вторую публикацию.
3. Подпись с истёкшим timestamp и подпись с чужим секретом отклоняются — по тестам.
4. Недоступный приёмник: доставка проходит всю лестницу backoff и уходит в
   dead-letter; replay после починки доходит — по тесту с фейковым временем.
5. `public_url` возвращается и сохраняется в юните.
